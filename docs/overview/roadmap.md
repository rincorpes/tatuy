# Roadmap

Tatuy is experimental, so this page describes direction rather than a fixed release contract.

## Current focus

- stabilize scene composition
- stabilize ECS usage patterns
- improve built-in activation and scheduling
- profile real game workloads
- improve lifecycle performance
- improve collision-heavy workloads
- improve documentation and examples
- mature development tooling

## Near-term

- bring all fundamental examples in line with current built-ins
- expand system/lifecycle reference documentation
- improve profiler exploration
- continue testing Tatuy with real game experiments
- identify performance bottlenecks through measurement

## Longer-term possibilities

These are directions, not commitments:

- SDL2 backend
- native render pipeline
- native system dispatch
- alternative ECS storage/query implementation
- visual profiler improvements
- richer editor/debug tooling

## Not current priorities

Tatuy is not currently trying to become:

- a Unity-sized editor
- a 3D engine
- a huge plugin marketplace
- an abstraction over every platform API
- a C++ engine with Python attached merely for scripting

The current goal is a capable, understandable 2D engine with Python gameplay.
